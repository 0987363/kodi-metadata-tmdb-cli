# 改造与验证结果

## 已落实的处理链

当前仅处理电影和剧集：具名通用 LLM 提取 → 按刮削配置顺序获取当前来源真实候选 → 指定 OpenAI 兼容模型或 Jev 判断 → 确认后写 NFO 与来源图片。

- `llms` 保存独立模型实例，`scraper` 保存模型任务引用、来源顺序、缓存与输出开关。旧单模型入口明确拒绝。
- TMDb 使用官方 API，TheTVDB 使用公开搜索请求与 HTML；作品编号是对应网站内电影或节目的身份线索，有编号则直取。
- 每次仅判断当前来源的候选；确认后不访问后续来源，无匹配才继续，协议与请求故障停止。
- 搜索按标题、中文名、原名及既有年份变体收集完整分页；缺失/矛盾/无进展/超限均报错。缓存键及封装版本为 3。
- 单查询原始条数及合并候选均最多 254，超过时不静默截断或预选。
- 已删除 Kodi JSON-RPC、ffmpeg/ffprobe、音乐视频、旧规则解析和闲置工具。原盘、人工约束、来源重试、扫描和监听保留。
- 关键词与临时后缀过滤在扫描、监听均生效；媒体根按目录组件和最长匹配确定唯一归属。

## NFO 与文件输出

电影/单集只写来源提供的正数分钟时长；移除无效语言标签和网站总季集数，单集季集坐标及零季保留。对象自身网站编号与网站确认的同对象跨站编号保留，不复制父节目的编号给单集。

普通电影 Logo 使用与视频同名前缀的 `-logo.png`，NFO 保留 clearlogo 来源 URL。原盘写电影根目录及原盘索引位置的同一份元数据，统一写入器负责单文件原子替换；不宣称多个文件整体回滚。

四端官方文档/源码核查与边界见 [专项报告](nfo-recognition-audit.md)，完整配置与流程见 [设计](metadata-providers.md)。

## 实施中发现并修正的边界

- 非法显式代理曾静默直连：构造校验及底层失败传输阻止外发。
- 搜索分页 404 曾被归为无结果：搜索 HTTP 404 明确失败，详情 404 仍表示对象缺失。
- 原盘内部普通扩展流文件曾被派发：原盘目录作为一个电影任务，内部条目排除。
- DVD 曾重复拼接 VIDEO_TS；蓝光缺少部分读端要求的根 NFO：路径与输出已统一。
- 原盘祖先判定曾越过配置根；全扫嵌套目录曾重复/错类；相对根和指定目录扫描曾遗漏子库：比较坐标和调度边界已按回归收口。

最终整体审查发现的相对节目根、畸形候选、顶层 null 提取和 SOCKS 停滞握手边界均已修复并通过复核；具体证据记录在 [progress.md](../progress.md)。

## 验证证据

采用先复现再修复的方式覆盖具名模型、来源顺序、分页、缓存、NFO 和路径；从配置文件启动真实 CLI，以受控模型/来源服务验证结果和失败保护。

最终版本 15 个测试包、167 个测试函数、519 个测试节点全部通过，包含 race；go vet、macOS、Linux amd64/arm64、Windows amd64 构建通过。整体审查的四项边界问题已集中修复并复核关闭，详情见 [progress.md](../progress.md)。

## 明确未验证的范围

按用户要求，四种媒体软件采用官方文档与源码核查，没有部署服务器或执行真实库导入。没有调用用户真实模型账户，不能声称实际媒体样本准确率已校准。

TheTVDB 实际网页和公开搜索响应此前已取得并用于结构核验；本机 Go 直连曾在连接阶段超时。部署网络可达性与真实 TMDb 凭据尚未验收，没有修改系统 DNS、代理、防火墙或硬编码 CDN。
