# TMDb 与 TheTVDB 单集详情批量获取调研

调研日期：2026-09-24。范围是本项目使用的 TMDb 官方 API，以及无需 API 密钥、无需登录的 TheTVDB 公开网页。通过官方资料与真实响应核验，不以缓存命中或 HTTP 200 代替批量能力判断。本轮未修改业务代码、未调用 LLM，也没有恢复 10 部节目的刮削验证。

## 结论

| 来源 | 已实测的批量能力 | 单集请求的边界 |
| --- | --- | --- |
| TMDb | 节目详情 API 入口可以追加多季、多集详情和各集演职员、图库、跨站编号；每次最多 20 个追加对象 | 当前 NFO 使用的单集字段已有批量取得路径，不应默认逐集调用独立详情接口；超过上限分批请求 |
| TheTVDB 网页 | 全集页提供跨季单集标题、简介、日期、电视网和剧照地址；季页面补充该季各集时长 | 已核验的匿名批量页面没有单集中文翻译和跨站编号；保持当前输出字段时，仅这些批量无法取得的信息需要单集页补取 |

因此，应先按整剧组织任务、识别和候选判断，再规划来源请求。单集 NFO 仍逐文件写入，不应逐文件重复整条节目刮削流程。

## 1. TMDb：从节目详情 API 入口组合请求

本次样本 `1668` 是《老友记》在 TMDb 的节目记录编号；路径中的 `season/1` 指该节目的第一季，`episode/1` 指相应季的第一集，不是独立的数据库记录编号。

`append_to_response` 是 TMDb 的查询参数，用于把指定相对路径的子资源附加到本次响应。响应以请求的相对路径作为对象键；不能要求它自动填入原有 `episodes` 数组。

### 多季及多集基础详情

真实请求：

```text
GET /3/tv/1668?language=zh-CN&append_to_response=season/1,season/2
```

返回节目详情和两季的完整单集数组，每季 24 集，共 48 集。单集数组包含：

- 单集记录编号、季号、集号及所属节目编号；这些标识用于把来源事实映射回本地文件。
- 中文标题、简介、首播日期、分钟时长、剧照地址、评分和评分人数。
- 单集制作人员和客串演员。不能把客串演员列表当成完整演员表。

另实测从同一节目详情 API 入口追加 `season/1/episode/1,season/1/episode/2`，成功获得两个独立单集详情对象。通常已请求整季时不需要重复获取这部分基础内容。

### 单集扩展字段也能合并

下列扩展字段均属于具体单集：`credits` 是该集演职员，`images` 是该集图片集合，`external_ids` 是该集在 IMDb、TheTVDB 等其他网站的记录编号。它们不属于节目或季，不能用父对象对应字段替代。

真实请求示例：

```text
GET /3/tv/1668?language=zh-CN&append_to_response=season/1/episode/1/credits,season/1/episode/1/images,season/1/episode/1/external_ids,season/1/episode/2/external_ids
```

四个扩展对象均实际返回。第一集的三个对象与单独调用第一集详情、追加同名字段的结果逐值相同。另用 8 个追加对象同时获取第一、二季及两季第一集的三个扩展对象，全部返回且字段结构正确。

### 必须区分入口与对象数

| 实测请求 | 结果 |
| --- | --- |
| 节目详情 API 入口追加两季 | HTTP 200，两季共 48 集 |
| 节目详情 API 入口追加两个单集详情 | HTTP 200，两个对象完整返回 |
| 节目详情 API 入口追加跨季的季详情和单集扩展，共 8 项 | HTTP 200，8 项全部返回 |
| 节目详情 API 入口追加 20 个单集的跨站编号对象 | HTTP 200，20 项全部返回 |
| 节目详情 API 入口追加 21 个单集的跨站编号对象 | HTTP 400，错误码 27，明确超过 20 项上限 |
| 季详情 API 入口追加 `episode/1,episode/2` | HTTP 200，但没有返回要求的追加对象 |
| 季详情 API 入口追加多个单集的演职员、图片、跨站编号路径 | HTTP 200，但没有返回要求的追加对象 |
| 季详情 API 入口追加 `credits,images,external_ids` | 返回季本身的扩展对象，单集数组没有因此增加对应字段 |

20 是追加对象总数，不是 20 集。每集需要三个扩展对象时，每集占三项；季详情和节目扩展对象也占用同一个上限。超过上限应拆分批次，不改成默认逐集获取。

官方文档说明了追加参数和 20 项上限。嵌套单集路径可从节目详情 API 入口批量取得的结论，来自本轮真实 API 核验。2020 年官方讨论曾表示单集跨站编号不能批量取得，但已与本轮实测不符，不能继续作为当前实现限制。

依据：[节目详情](https://developer.themoviedb.org/reference/tv-series-details)、[季详情](https://developer.themoviedb.org/reference/tv-season-details)、[追加响应](https://developer.themoviedb.org/docs/append-to-response)、[官方 OpenAPI](https://developer.themoviedb.org/openapi/tmdb-api.json)、[2020 年历史讨论](https://www.themoviedb.org/talk/5fa6829f21621d0040f666b3)。

## 2. TheTVDB：合并全集页和季页面

无需调用需要密钥的 TheTVDB API。以下结论来自匿名访问的公开 HTML，以及页面公开加载的脚本。

### 全集页面具有多集详情，不只是目录

`/series/friends/allseasons/official` 的实际 HTML 中，每个单集条目包含正式季集号、指向单集的链接、标题、首播日期、电视网、简介和可选剧照。链接末尾数字是 TheTVDB 单集记录编号，可用于关联季页面与详情页面；剧照地址位于图片元素的 `data-src` 属性。

| 样本 | 全集页季数 | 单集条目 | 有简介 | 有剧照地址 |
| --- | ---: | ---: | ---: | ---: |
| Friends | 10 | 236 | 236 | 235 |
| Breaking Bad | 5 | 62 | 62 | 62 |

本项目现有全集解析器只使用其中部分信息，尚未读取剧照。因此不能因当前解析结构没有图片字段，就断言网站必须逐集获取图片。

### 季页面批量补齐时长

`/series/friends/seasons/official/1` 的表格包含每集季集号、单集链接、名称、播出日期、电视网和分钟时长。实测《老友记》第一季 24 集全部有时长，《绝命毒师》第一季 7 集全部有时长。

全集页与所需季页面通过相同的 TheTVDB 单集记录编号关联，可以批量获得标题、简介、日期、时长和剧照。关联时仍须核对节目归属与季集号，不能只凭数组位置拼接。

### 已确认的匿名批量页面缺口

- 两部节目全集页没有嵌入单集中文翻译，也没有 IMDb 等单集跨站链接。
- 季页面中的单集表格同样没有嵌入中文翻译。页面说明首选语言来自账户设置。
- 对 Friends 全集页发送中文 `Accept-Language` 请求头，以及添加 `language=zho` 查询参数，首集标题仍为英语，HTML 仍没有中文翻译块。
- 作为对照，Friends 第一集详情页确有中文标题、简介翻译块及 IMDb 单集链接。
- 页面公开的 Bulk Editor 入口匿名访问会跳转登录页，不能当作当前无需登录方案的批量详情来源。没有尝试登录或修改站点数据。
- 翻译切换脚本读取页面已有的翻译块，没有在该交互中发起批量翻译请求。

这证明本次核验的匿名页面不能覆盖这些字段，并不宣称已穷尽网站所有未来或未公开接口。按目前可确认的接入能力，若要保留这些单集字段，可以在批量采集后对相应单集补取详情；该请求不得重新执行节目识别、搜索和候选判断。

Friends 全集页缺图的一集，详情页也没有图片。来源本身缺失值与批量页面没有提供该类字段是两种情况；不能把所有空值都当成补请求的理由。

依据：[Friends 全集](https://thetvdb.com/series/friends/allseasons/official)、[Friends 第一季](https://thetvdb.com/series/friends/seasons/official/1)、[Friends 第一集](https://thetvdb.com/series/friends/episodes/303821)、[Breaking Bad 全集](https://thetvdb.com/series/breaking-bad/allseasons/official)、[Breaking Bad 第一季](https://thetvdb.com/series/breaking-bad/seasons/official/1)。

## 3. 对后续改造的约束

1. 保留此前完成的项目清理、全量视频目录复现与固定的 10 部节目样本；不更换样本。
2. 将同一部剧的本地文件集合归入一个任务，集中进行通用 LLM 分析、按来源顺序定位与候选判断；电影流程不受影响。
3. TMDb 在节目详情 API 入口规划所需季详情和单集扩展路径，每批不超过 20 个追加对象；核对每项实际返回，不以 HTTP 200 判断完整性。
4. TheTVDB 先取节目页、全集页及涉及的季页面，合并已能批量取得的事实。仅对仍需要且批量入口无法提供的字段补取单集页。
5. 批量页面的请求错误、解析错误、身份冲突必须报告；不得将故障解释为平台不支持批量，再自动转为逐集请求。
6. 每部剧写一次节目 NFO 和共有图片；每个本地视频仍写自己的单集 NFO。相同来源单集对应多个本地版本时，共用事实数据。
7. 验证需覆盖多季多集、追加对象上限、字段等价、重复文件复用、来源顺序及请求计数，再恢复 10 部节目样本的真实运行。每部只测一集不能证明批处理生效。

这里尚未定义新的业务配置字段或实施接口；业务改造完成前，现有程序仍是逐视频执行完整流程。

## 4. 本地证据

只读调研产物保存在项目忽略目录 `.validation/platform-batch-20260924/`：

- `tmdb-probes.json`：11 组官方 API 请求的脱敏参数、状态与返回结构。
- `tmdb-*.json`：对应实际响应，包括单集对照、跨季批量和 20/21 项边界。
- `tvdb-probes.json`、`tvdb-additional-probes.json`：两部节目批量页面的 DOM 统计、中文请求及登录边界检查。
- `tvdb-*.html`、`tvdb-vendor.js`：本次实际公开页面和公开脚本快照。

读取了原 config.json 中的 TMDb 配置，仅向其已配置的官方 API 发起查询；未修改原配置。报告与命令输出不包含密钥。本轮没有执行真实 LLM 判断、NFO 生成或媒体服务器导入，因此不将平台能力核验表述为整条刮削流程已经通过。
